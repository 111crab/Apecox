更新日期：2026-09-22；Unreal Engine 5.8。

本清单只保留本轮尚未执行的调整与验证。三个蓝图的创建、模型配置、地图摆放和上一轮已经通过的项目均已移除。

## 一、调整现有争夺点蓝图

本轮只有这一项需要手工修改蓝图；AI 开火频率、护盾门槛和命中后血条均已由 C++ 完成，不需要连接蓝图节点。

1. 重新打开编辑器，进入：`/Game/Blueprints/AI`。
2. 双击打开：`BP_ApecoxAIObjectivePoint`。
3. 点击顶部 `Class Defaults`。
4. 在 `Details > Apecox | AI | Objective` 修改：
   - `Search Duration Min = 1.0`
   - `Search Duration Max = 2.0`
5. 以下值保持不变：
   - `Selection Weight = 1.0`
   - `Acceptance Radius = 140`
   - `Enabled = true`
6. 点击 `Compile` 和 `Save`。
7. 已经放入地图的争夺点实例应自动继承新值。如果某个实例的 Search Duration 一栏显示黄色回退箭头，说明它以前单独覆盖过数值：点击该箭头恢复蓝图默认值。
8. 中央争夺点实例若已单独设置 `Selection Weight=2.0`，继续保留，不要恢复该项。

## 二、AI 攻击与争夺点节奏验证

1. 无目标时观察 AI：到达争夺点后应只停留约 `1–2s`，环视频率也比上一版更快，然后前往下一个点。
2. 进入 `2400 cm` 索敌范围并保持无遮挡：AI 应在约 `0.25–0.55s` 后开始第一轮射击。
3. AI 单轮点射约持续 `0.3–0.6s`；点射间停顿约 `0.35–0.8s`，攻击欲望应比上一版明显更强，但仍保留点射节奏。
4. 射程内 AI 的随机换位间隔约为 `0.55–1.2s`，应更频繁地横移或前后调整位置。
5. 原有边界保持不变：`2400 cm` 内且有视线才索敌、`1800 cm` 内才开火、超过 `3000 cm` 或丢失视线约 `2s` 后脱战。

## 三、护盾升级门槛验证

本轮采用“每段成本”解释：白色到蓝色需要 `500` 点；到达蓝色后还需要 `1000` 点到紫色，所以累计阈值为 `500/1500`。

1. 新玩家仍以白色 `25` 护盾开始，HUD 应显示距离蓝色还需 `500` 点。
2. 累计点数小于 `500` 时保持白色；达到 `500` 时升级蓝色，最大护盾变为 `50`。
3. 蓝色刚升级时，HUD 应显示距离紫色还需 `1000` 点。
4. 累计 `1499` 点仍为蓝色；累计达到 `1500` 时升级紫色，最大护盾变为 `75`。
5. 护盾电池仍增加 `300` 点并补满当前等级护盾。因此白色拾取一次仍是白色，第二次达到 `600` 后成为蓝色；累计拾取五次达到 `1500` 后成为紫色。
6. 紫色仍在 `1500` 封顶；死亡重生继续继承当前等级和累计点数。

## 四、敌人血条显示验证

1. 进入 PIE 后先观察附近 AI：未攻击任何 AI 时，不应看到任何敌人血条。
2. 射击并实际伤害某个 AI：只在该 AI 头顶显示血条和生命数值，同时原命中准星反馈保持正常。
3. 不攻击第二个 AI：第二个 AI 仍不显示血条。
4. 连续约 `4s` 不再命中第一个 AI：其血条应自动隐藏。
5. 血条隐藏前再次命中同一 AI：显示时间应重新延长约 `4s`。
6. AI 死亡时血条立即消失；该 AI 重生后，在再次被玩家命中前不显示。

## 五、Listen Server 双窗口验证

1. 设置 `Number of Players=2`、`Net Mode=Play As Listen Server`，打开 Host 与 Client 两个独立窗口。
2. Host 命中某个 AI：只有 Host 的 HUD 显示该 AI 血条；Client 在没有命中它时不应凭空显示。
3. Client 命中另一个 AI：只有 Client 显示自己命中目标的血条。
4. 两端应看到一致的 AI 高频点射、换位和争夺点移动结果；血条的“是否揭示”属于各自本地 HUD 状态。
5. Host 与 Client 的护盾进化点分别计算，并都使用累计 `500/1500` 阈值。

## 本轮反馈格式

- AI：争夺点停留、开火间隔和战斗换位是否更积极但仍然自然；
- 护盾：白→蓝 `500`、蓝→紫再需 `1000`、累计 `1500` 封顶是否正确；
- 血条：初始隐藏、仅显示自己命中的目标、约 `4s` 后隐藏、再次命中刷新是否正确；
- 多人：Host/Client 的血条揭示是否相互独立。
