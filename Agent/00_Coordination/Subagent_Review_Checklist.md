# 子代理实施与审查规范

更新日期：2026-08-05

## 子代理报告最低要求

- 中文说明实际修改文件及是否超出 Prompt。
- 列出新增/修改的 C++ 类名、父类、文件路径和职责。
- 列出成员变量名、类型、UPROPERTY 暴露和作用。
- 列出函数名、参数、返回值、UFUNCTION 暴露和作用。
- 说明是否修改 Build.cs、Config、蓝图、地图或资产。
- 说明是否新增 GameplayTag、Attribute、GA、GE、GameplayCue、DataAsset 或 AbilityTask。
- 给出编译命令、结果和未执行项。
- 给出用户需要完成的 UE 编辑器步骤和验证标准。

## Codex 审查顺序

- 范围：是否只修改批准内容，是否误动二进制资产或用户改动。
- 设计：职责是否正确，是否制造万能类、重复生命周期或过早抽象。
- 命名：新类、成员、函数、Tag 和资产名是否需要用户再次批准。
- UE C++：反射、GC、Include、模块依赖、Authority 和生命周期是否正确。
- GAS：ActorInfo、SpecHandle、PredictionKey、Commit/Cancel/End、Task 清理、GE/Cue 边界是否正确。
- 网络：服务端真相、本地预测、远端表现、RPC/复制所有权是否正确。
- 验证：编译不替代 PIE；多人功能必须说明两端分别看到什么。

## 给用户的审查反馈必须包含

- 是否通过及剩余风险。
- 新增公开 C++ API 的完整清单。
- 需要用户确认的命名或职责。
- 详细 UE 手工配置。
- 明确成功标准。
- 当前是否适合做功能提交。
