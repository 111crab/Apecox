# Apecox UE 客户端面试学习手册

更新日期：2026-09-22

## 使用方法

这份手册从简历上的四条项目经历反向展开知识。每个模块按以下顺序学习：

1. 用一分钟说清它解决了什么问题。
2. 不看文档画出运行链路。
3. 打开列出的源码入口，确认每一步由哪个对象负责。
4. 回答追问题，并至少说出一个设计取舍。
5. 完成自测题，检查自己是否只记住了名词。

目标是能够从玩家输入讲到服务器结算、网络复制和客户端表现。

## 一、Gameplay Framework 与 GAS 生命周期

### 基础职责

- `GameMode` 只存在于服务器，负责规则裁定。
- `GameState` 向所有客户端复制公共比赛状态。
- `PlayerState` 表示玩家身份以及跨 Pawn 生命周期的数据。
- `PlayerController` 处理拥有者输入和私有库存。
- `Character/Pawn` 是一次出生周期内的可控制实体。
- ASC 的 Owner Actor 决定长期归属，Avatar Actor 是当前执行能力的物理实体。

### 项目链路

```text
PlayerState 创建 ASC + AttributeSet
  -> Character 被占有或收到 PlayerState
  -> InitAbilityActorInfo(PlayerState, Character)
  -> Authority 授予基础 AbilitySet
  -> Equipment 装备步枪并授予武器 AbilitySet
  -> Health 归零发送 GameplayEvent.Death
  -> DeathAbility 取消普通能力并结束 Pawn 生命周期
  -> GameMode 延迟生成新 Pawn
  -> 原 PlayerState/ASC 绑定新 Avatar
```

玩家护盾等级和进化点属于 PlayerState/AttributeSet，所以死亡换 Pawn 后可以继承；移动、镜头和动画等 Pawn 瞬时状态重新初始化。

### 设计取舍

ASC 没有放在 Character 上，因为 Character 会在死亡时销毁。AbilitySet 保存 Granted Handles，卸下武器时只撤销该武器授予的能力，避免未来加入英雄技能后使用“清除全部 Ability”造成误删。

ASC 使用 Mixed 复制：拥有客户端接收完整 GameplayEffect 信息，远端主要接收公开属性和 GameplayCue。

## 二、GameplayTag 与输入路由

### 输入链路

```text
物理按键
  -> Enhanced Input / InputAction
  -> UApecoxInputConfig 映射 Native GameplayTag
  -> Character/InputComponent 分发
  -> Ability 输入：ASC Pressed/Held/Released 缓存
  -> 普通事务：Character、CMC 或 Equipment 显式处理
```

项目使用 Tag 表达稳定、跨系统的语义：

- `InputTag.*`：输入意图。
- `State.Input.AbilityBlocked`：统一阻止输入激活 Ability。
- `State.Death.*`：死亡生命周期状态。
- `GameplayEvent.Death`：触发 DeathAbility 的事件。
- `GameplayCue.Weapon.*`：开火和命中表现通道。
- `SetByCaller.Damage`：GE 动态伤害参数。

速度、弹药、AimAlpha、RootYawOffset 等连续数据仍使用强类型变量。GameplayTag 不是 bool 和数值的通用替代品。

### 为什么移动没有全部 Ability 化

CharacterMovement 已经提供移动预测、服务器校正、Movement Mode 和蹲伏复制。开火需要 Ability 激活、SourceObject、TargetData 和服务器事务，因此适合 GAS；基础移动继续由 CMC 处理能减少职责重复。

## 三、数据驱动武器与对象职责

### 三层模型

```text
Weapon Definition
  不可变类型配置：FireConfig、ReloadConfig、AbilitySet、PresentationDefinition

Weapon Instance
  单把武器运行时状态：弹匣、备用弹药、Burst/Shot 账本

Presentation Definition
  FP/TP Mesh、Montage、声音、VFX、Socket 和挂载变换
```

`UApecoxWeaponDefinition` 使用 `TInstancedStruct<FApecoxWeaponFireConfig>` 保存受基类约束的射击配置。它允许后续增加其他射击模型，同时避免把步枪参数硬编码在 Character 中。

Definition 可以由同类武器共享；Instance 必须独立保存每把武器的弹药和连发状态。如果把弹药放进 DataAsset，多把枪会错误共享运行时数据。

### Inventory 与 Equipment

- Inventory 位于 PlayerController，使用 OwnerOnly FastArray 保存私有物品和武器槽。
- Equipment 位于 Character，管理当前装备、AbilitySet、FP/TP 表现和公开摘要。
- 远端只接收第三人称表现所需的公开状态，不获得拥有者完整库存。

## 四、服务器权威实体弹丸

### 完整链路

```text
InputTag.Weapon.Fire
  -> UApecoxProjectileFireAbility
  -> 本地构造 FApecoxRangedShotTargetData
  -> Server 接收射击意图
  -> 校验比赛阶段、SourceObject、装备、射速、弹药和视点
  -> ShotId/BurstId 驱动确定性散布
  -> 视点到玩法枪口 Sweep
  -> Authority 生成 AApecoxWeaponProjectile
  -> Projectile Hit
  -> Instant GE + SetByCaller.Damage + HitResult
  -> AttributeSet 结算护盾/生命/进化点
  -> HealthComponent 检测死亡
```

TargetData 只描述“玩家想射击”，不提交可信命中结果。最终散布、弹丸、碰撞和伤害由服务器决定，避免客户端伪造 HitResult。

散布使用服务器认可的 Burst/Shot 序号与随机流生成，使连续射击有可控规律，并让同一发参数可重现。相机到枪口的 Sweep 处理近墙遮挡，防止相机看到目标但枪口在墙后生成弹丸。

## 五、Gameplay 与客户端表现分离

权威 Projectile 负责碰撞和伤害；短寿命本地 Tracer 负责让高速子弹可见。服务器接受射击后通过 `NetMulticast, Unreliable` 下发实际起点、方向、速度和重力，各端生成无碰撞 Tracer。

这个方案保证：

- Tracer 丢失只影响视觉，不影响伤害。
- 不依赖高速复制 Actor 在命中前到达客户端。
- Dedicated Server 不创建视觉对象。
- 客户端不能利用 Tracer 伪造碰撞。

Impact GameplayCue 消费服务器命中结果，生成粒子、声音和弹孔。HUD 的命中 X 也只在服务器确认实际伤害后显示；目标 AI 血条只在本地玩家造成伤害后短暂揭示。

## 六、伤害、护盾与属性结算

项目规则：步枪基础伤害 13；玩家初始 100 生命和 25 白色护盾；伤害先扣护盾，溢出部分扣生命；白到蓝需 500 进化点，蓝到紫再需 1000，累计阈值 500/1500。

AttributeSet 使用实际扣除值授予进化点。过量伤害不额外计点，自伤、友军伤害和 AI 来源不会让玩家成长。护盾电池增加 300 点并补满当前等级护盾；血包恢复生命；AI 不使用护盾成长。

Projectile 和未来其他伤害源都提交 Damage GE。AttributeSet 是统一属性结算点，在这里处理护盾优先可以避免每种伤害来源各写一套逻辑。武器通过 `SetByCaller.Damage` 向统一的 Instant GE 注入本次伤害值。

## 七、第一人称动画组织

`UApecoxCharacterAnimInstance` 从 Character、CMC 和 Equipment 读取状态并缓存，不选择具体动画资产，也不决定 Gameplay 状态。`UApecoxFirstPersonAnimInstance` 增加 ADS、Look Sway、模型后坐力、Turning 和左手 IK 数据。

### Pose Composition

```text
基础持枪/移动 Pose
  -> 地面、空中、蹲趴状态
  -> ADS、Turning、Lean 等叠加层
  -> Fire/Reload/Inspect/Equip Montage
  -> 程序化 Weapon Recoil
  -> 左手 FABRIK
```

状态机适合互斥且持续的状态；Montage 适合有明确开始和结束的一次性动作；Additive 适合增加后坐、瞄准或转向偏移；IK 放在末端修复最终接触关系。

换弹和检视期间，动画曲线降低 IK Alpha，把左手控制权暂时交给 Montage；动作结束后恢复 IK。程序化后坐力放在 FABRIK 前，使枪械移动后左手仍跟随最终握点。

服务器 ReloadConfig 决定扣弹提交点和事务总时长。不同视角的 Montage 可以通过播放倍率对齐同一事务时间窗；AnimNotify 可以播放声音和视觉事件，不作为扣弹的唯一权威来源。

## 八、第一/第三人称分离表现

本地玩家使用第一人称操控，其他观察者看到第三人称角色。项目要求 Gameplay 行为一致，不要求两个视角使用相同骨骼、动画序列或逐帧姿势。

共享内容包括 CMC 移动状态、GAS 开火/伤害/死亡状态、Equipment 装备/换弹/镭射事务，以及同一个服务器事务时间窗。第一人称使用 RAR Arms/Weapon，第三人称使用 Lyra Manny/Rifle，两套 AnimBP 各自选择适合其骨骼和观察距离的 Pose。

### 第三人称动画链路

```text
Locomotion / Jump / Crouch
  -> UpperBody Reload
  -> Fire Additive
  -> Aim Offset
  -> Turn in Place / Rotate Root Bone
  -> 左手 IK
```

Aim Offset 修改上半身后，左手 IK 再把手约束回枪身。Turn in Place 的 RootYawOffset 只改变观察端 Mesh 视觉，不修改 Actor、ControlRotation、Projectile 或镭射的玩法方向。

Inventory 和 Weapon Instance 对拥有者私有。Equipment 复制轻量公开摘要，让 Simulated Proxy 创建第三人称武器、播放 Montage 和显示镭射。`PawnClientRestart` 幂等修复“装备状态先到、客户端占有后到”的复制顺序。

## 九、动作互斥、打断和意图保留

| 当前状态 | 新输入 | Gameplay 结果 |
| --- | --- | --- |
| 冲刺 | 开火 | 先取消冲刺，再进入普通移动/静止开火 |
| 趴姿移动 | 开火 | 先停止爬行，保持趴姿静止开火 |
| 趴姿 | 跳跃 | 只尝试站起，头顶受阻则保持趴姿 |
| 换弹/检视/冲刺 | 镭射 | 保留开启意图，动作期间隐藏 Beam，结束后恢复 |
| 死亡 | 普通输入/Ability | Death Tag 阻止能力并清空输入 |
| PostMatch | 开火/AI 决策 | 不再产生新的战斗事务 |

动画之间能否混合只是结果。真正的规则应由 Gameplay 层明确，例如冲刺时按开火是拒绝开火，还是取消冲刺后开火。项目采用后者，因此先完成状态转换，再提交开火事务。

镭射区分“用户希望开启”和“当前允许展示”：换弹期间枪管方向不适合显示 Beam，只临时关闭实际表现，不能抹掉用户意图。

## 十、AI、GameMode 与 HUD 闭环

AI 没有复制另一套战斗代码。Authority 为 AI 装备同一个 Weapon Definition，复用 Projectile Ability、弹药、换弹、Damage GE、死亡和重生；AIController 只产生移动和射击意图。

```text
无目标
  -> 按权重选择 AIObjectivePoint
  -> NavMesh MoveTo
  -> 到达后停留并环视
  -> 局部范围发现有视线的存活玩家
  -> 反应延迟
  -> 短连发 / 停火 / 换弹 / 重新定位
  -> 丢失目标后返回争夺点
```

GameMode 是唯一计分裁判，负责击杀归因、团队加分、15 分胜利和重生；GameState 复制双方比分、目标分、比赛阶段和胜方；HUD 只观察状态，不自行裁定胜负。

当前 AI 是面试 Demo 所需的轻量 Controller 状态逻辑，没有使用 Behavior Tree、EQS、AI Perception、掩体或完整难度系统。可以把这些作为扩展方向，不应写成已经完成。

## 七天复习顺序

1. **框架与 GAS**：画出 GameMode、GameState、PlayerState、Controller、Character、ASC 的关系，讲清 Owner/Avatar 和 Mixed 复制。
