# Apecox 产品与求职作品方向

更新日期：2026-08-05

## 顶层目的

Apecox 首先是一个 UE 游戏客户端求职作品，其次才是一款内容完整的游戏。它需要证明：

- 能理解和扩展 UE Gameplay Framework 与 GAS。
- 能实现多人权威、预测、复制和调试。
- 能将武器、技能、属性、动画、UI 和表现组织成可维护运行链路。
- 能控制项目范围，交付可运行、可解释、可复现的垂直切片。

## 建议产品形态

小规模多人英雄射击竞技场：

- 本地玩家以第一人称战斗表现为主。
- 其他玩家需要可靠的第三人称世界表现。
- 每名英雄具有 Health、Shield、武器槽和少量技能。
- 第一阶段以步枪闭环为核心，再扩展手枪、霰弹枪、狙击枪或特殊武器。
- 支持拾取、弹药、换弹、切枪和少量配件。
- 地图先是紧凑测试场，不做大逃杀大地图、缩圈、复杂经济或大量 AI。

视角已经确定：玩家固定使用第一人称操控，不提供第三人称切换；Owning Player 使用 FP Arms/Weapon，其他客户端使用 TP Manny/Weapon。两套表现共享玩法状态，不强求共用动画资产或 AnimBP。

## 技术区分度

作品价值不来自枪械数量，而来自以下可展示证据：

- 客户端预测射击与服务器验证。
- TargetData/PredictionKey 或等价网络链路。
- ASC 的 Owner/Avatar 生命周期和重生处理。
- AbilitySet、输入槽、装备/武器实例和技能配置的职责分离。
- Health/Shield、伤害、死亡、复活的清晰分层。
- 第一/第三人称动画、枪口、命中和 Cue 的一致性。
- 网络模拟条件下的测试记录。
- 清晰的代码注释、运行链路文档和架构取舍。

## 资产策略

- 优先使用 Stephen_FPS 的 UE5 Manny/Quinn 步枪/手枪动画完成第一把步枪。
- Modern Guns Pack 提供武器族、第一人称手臂、附件、音频和枪口表现；其 UE4 骨骼需要重定向评估。
- Rifle Pro 作为第三人称步枪动作库，版本较老，优先走 FBX 重导入或 IK Retarget。
- 第三人称动画按 Rifle、Pistol、Heavy 语义族复用，不要求每把枪完全独立。
- 第一人称可对关键动作采用更精确的武器族动画。
